# IAM-Infra

Данный репозиторий содержит конфигурацию для развертывания общего кластера Apache Kafka и ZooKeeper. Инфраструктура спроектирована для обеспечения взаимодействия между независимыми микросервисами через выделенную Docker-сеть.

----

<details>
<summary><strong>Локальное развертывание</strong></summary>

Перед запуском убедитесь, что в вашей системе установлены Docker и Docker Compose V2.

Порядок запуска:
1. Создание общей сети для взаимодействия между разными docker-compose проектами необходимо создать внешнюю сеть вручную:
```sh
docker network create kafka-net
```

2. Подготовка конфигурации скопируйте шаблон переменных окружения и при необходимости измените порты:
```sh
cp .env.example .env
```

3. Запуск контейнеров Запустите инфраструктуру в фоновом режиме:
```sh
docker-compose up -d
```

4. Проверка работоспособности проверьте, что брокер доступен, просмотрев логи:
```sh
docker-compose logs -f kafka
```
</details>

<details>
<summary><strong>Базовые команды</strong></summary>

| Команда                           | Makefile cmd | Описание                                                |
|:----------------------------------|:-------------|:--------------------------------------------------------|
| `docker-compose up -d`            | `make up`    | Запуск Kafka и ZooKeeper в фоновом режиме.              |
| `docker-compose stop`             | `make stop`  | Остановка сервисов без удаления контейнеров.            |
| `docker-compose down`             | `make down`  | Полная остановка и удаление контейнеров инфраструктуры. |
| `docker-compose logs -f kafka`    | `make logs`  | Просмотр логов брокера в реальном времени.              |
| `docker network ls`               | `make net`   | Просмотр списка сетей (проверка наличия `kafka-net`).   |
| `docker exec -it kafka /bin/bash` | `make exec`  | Вход в контейнер Kafka для использования CLI утилит.    |

</details>

<details>
<summary><strong>Переменное окружение</strong></summary>

Файл `.env` управляет версиями образов и пробросом портов на хост-машину.

| # | Переменная              | Описание                                               | Значение по умолчанию             |
|:-:|:------------------------|:-------------------------------------------------------|:----------------------------------|
| 1 | `ZOOKEEPER_IMAGE`       | Docker-образ для сервиса координации ZooKeeper.        | `confluentinc/cp-zookeeper:7.4.0` |
| 2 | `KAFKA_IMAGE`           | Docker-образ для брокера Kafka.                        | `confluentinc/cp-kafka:7.4.0`     |
| 3 | `KAFKA_UI_IMAGE`        | Docker-образ для графического интерфейса Kafka UI.     | `provectuslabs/kafka-ui:latest`   |
| 4 | `ZOOKEEPER_CLIENT_PORT` | Порт, на котором ZooKeeper ожидает подключения.        | `2181`                            |
| 5 | `KAFKA_EXTERNAL_PORT`   | Порт для приложений вне Docker (localhost).            | `9092`                            |
| 6 | `KAFKA_INTERNAL_PORT`   | Порт для связи внутри сети `kafka-net`.                | `29092`                           |
| 7 | `KAFKA_UI_PORT`         | Порт для доступа к графическому интерфейсу в браузере. | `8080`                            |
| 8 | `DOCKER_NETWORK_NAME`   | Имя внешней сети для связи между микросервисами.       | `kafka-net`                       |

</details>

<details>
<summary><strong>Сетевое взаимодействие</strong></summary>

Брокер настроен на работу с использованием механизма **Advertised Listeners**, что позволяет подключаться к нему двумя способами:

#### 1. Внешнее подключение (Host Machine)
Если ваш NestJS сервис запущен локально через `npm run start:dev`:
- **Адрес брокера:** `localhost:9092` (значение из `KAFKA_EXTERNAL_PORT`)
- **Протокол:** `PLAINTEXT`

#### 2. Внутреннее подключение (Docker Network)
Если ваш сервис запущен в собственном Docker-контейнере:
- **Адрес брокера:** `kafka:29092` (имя сервиса и `KAFKA_INTERNAL_PORT`)
- **Протокол:** `PLAINTEXT_INTERNAL`

#### Настройка внешних микросервисов:
Чтобы другой `docker-compose` проект мог подключиться к этой сети, добавьте в его конфигурацию:

```yaml
networks:
  default:
    external:
      name: kafka-net
```
</details>

<details>
<summary><strong>Инструменты мониторинга (UI)</strong></summary>

Для визуального управления кластером используется **Kafka UI**.

- **URL:** `http://localhost:8080` (зависит от переменной `KAFKA_UI_PORT`)
- **Возможности:**
  - Просмотр списка топиков и их конфигурации.
  - Чтение сообщений из очередей в реальном времени.
  - Мониторинг Consumer Groups (кто и сколько сообщений не успел обработать).
  - Создание и удаление топиков через браузер.

</details>
